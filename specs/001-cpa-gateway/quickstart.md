# Проверка после реализации

Эти шаги предназначены владельцу реализации; на этапе документов они не выполнялись. Не использовать реальный профиль пользователя без отдельного разрешения. Не выполнять tool calls, возвращённые ограниченным вызовом.

## Условия

1. Подготовить отдельный локальный DSH-профиль и установленный пакет новой версии; записать его версию, пути и способ полного перезапуска.
2. Подготовить контролируемый CPA endpoint и тестовый ключ. Не сохранять ключ и содержимое сообщений в отчёт.
3. На тестовой копии создать legacy profile с выбранными моделями, efforts и совместимыми настройками; сохранить сессию с `CLIProxyAPI` и model-id.

Проверенные launcher-команды внутри локального Docker (не пользовательский профиль): установить CLI `npm install --prefix /tmp/dsh-cli-proof --ignore-scripts @deepseek-ai/dsh@0.2.2-rc.1` и pnpm; задать `DSH_HOME=/tmp/dsh-cpa-proof-home`. Однократно создать профиль без запуска браузера: `node /tmp/dsh-cli-proof/node_modules/@deepseek-ai/dsh/lib/bin.js --profile cpa-proof --from-default-profile web --dump-config`. Установить собранный tarball: `node /tmp/dsh-cli-proof/node_modules/@deepseek-ai/dsh/lib/bin.js plugin --profile cpa-proof add /tmp/plugin.tgz`. Повторный запуск использует `--profile cpa-proof` без `--from-default-profile`, с `--no-open` и отдельным локальным портом. Это подтверждённая синтаксическая схема, ещё не отчёт о выполнении.

`--profile` принимает имя, не произвольный путь. `--from-default-profile` заменяет каталог профиля; нельзя повторять его при проверке сохранения/переноса. Обычный headless создаёт новую сессию: сохранённую сессию проверять в Web UI через существующий CDP9222 либо через документированный клиент resume, а не выдавать новый одноразовый запрос за continuation.

## Проверки

1. Выполнить `npm run check` в корне репозитория и отдельно прогнать поддерживаемые версии SDK 1.3 и 1.5 по lock/матрице реализации. Сохранить команды и реальные результаты.
2. Импортировать legacy profile; полностью перезапустить DSH. Открыть ранее сохранённую сессию и выполнить один ограниченный запрос через существующий CPA с исходным набором tools. Проверить поток, schemas, attribution и request IDs; не выполнять возвращённые инструменты.
3. В форме одновременно изменить URL, credential и выбор. Зафиксировать единый подтверждённый результат и readback; вызвать конфликт и UNKNOWN, убедиться, что draft сохранён. Новый endpoint не должен получить старый ключ без явного выбора.
4. Воспроизвести отказ после legacy unset и перезапуск, конфликт чужой записи и откат до и после новых изменений. Записать фактические состояния, включая возможный краткий NO_ADAPTER.
5. Выключить все модели и удалить доступность обязательного credential: route не должен сообщать готовность native onboarding. Восстановить условия; проверить auth=none отдельно и стабильность старого prepared-call.
6. Проверить stale/повреждённый cache, отказ refresh, изоляцию профилей/generations, HTTP/SSE/abort/timeout, усилия, images/replay, отсутствие добавленных inference retries и сохранение языков/metadata/поиска/массового выбора.
7. В Models нажать честно названную кнопку «Открыть плагины», выбрать CLIProxyAPI и открыть его настройки. Не считать двухшаговый переход доказательством полноценной строки или прямого deep-link.

## Отчёт

Записать команду, версию, изолированный профиль, сценарий, результат и ограничения. Unit/synthetic success не доказывает миграцию или desktop пользователя; реальное обновление и наблюдение пользовательского Desktop — отдельный этап. Контракты: [gateway.md](contracts/gateway.md); состояние: [data-model.md](data-model.md).
